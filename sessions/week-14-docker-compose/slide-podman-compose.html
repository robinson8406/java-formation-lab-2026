Demo · Dockerfile

Build con JDK, runtime con JRE

Usamos el nombre Dockerfile — el más extendido — y Podman lo reconoce igual que Containerfile

🔨 Stage 1 — builder

FROM maven:3.9-eclipse-temurin-21 AS builder
WORKDIR /app
COPY pom.xml ./
RUN mvn dependency:go-offline
COPY src ./src
RUN mvn package -DskipTests
Compila el jar — esta capa no viaja a producción.

🚀 Stage 2 — runtime

FROM eclipse-temurin:21-jre AS runtime
WORKDIR /app
RUN addgroup --system appgroup \
 && adduser --system --ingroup appgroup appuser
USER appuser
COPY --from=builder /app/target/*.jar app.jar
EXPOSE 8080
ENTRYPOINT ["java", "-jar", "app.jar"]
Solo JRE, usuario no-root, sin herramientas de build.
✅ sin JDK en runtime ✅ usuario no-root ✅ imagen < 300MB

Variables de entorno

Credenciales fuera del código

Hoy el week-14-start trae la URL y la contraseña de la BD hardcodeadas

❌ application.properties (hoy)

spring.datasource.url= jdbc:postgresql://localhost:5432/retaildb spring.datasource.username=retail spring.datasource.password=retail123

✅ .env.example (lo que vas a crear)

SPRING_DATASOURCE_URL= jdbc:postgresql://db:5432/retaildb SPRING_DATASOURCE_USERNAME= SPRING_DATASOURCE_PASSWORD= POSTGRES_DB=retaildb POSTGRES_USER= POSTGRES_PASSWORD=
⚠️

Regla de oro: las credenciales nunca van en el Dockerfile ni en el compose.yml directamente — siempre vía .env, y .env siempre en .gitignore.

Cómo se revisa el PR

Verificación y checklist

Esto es lo que el reviewer va a ejecutar y validar

1
podman compose up --build

Levanta app + db sin errores.

2
GET /actuator/health

Responde 200 en http://localhost:8080.

3
podman images

Verifica que el runtime pese < 300MB.

4
mvn verify

Debe quedar en verde antes de abrir el PR.

Checklist del reviewer

✓ Multi-stage: builder (JDK) / runtime (JRE)
✓ Usuario no-root en el stage runtime
✓ Health check pg_isready en db
✓ app depende de db con service_healthy
✓ Volumen persistente + red app-network
✓ .env.example presente, .env en .gitignore
